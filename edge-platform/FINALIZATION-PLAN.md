## Срез 2 — физическая эксплуатационная приёмка

1. **Fresh VM:** сначала `/host status application-acceptance-3 --deep`; при отсутствии целевого native owner — один штатный `/host apply application-acceptance-3` в Issue #1 с существующим Vultr first-use. До provider CREATE доказать Git desired/ReleaseSet, source Worker trust, exact CredentialRef и доступность authorizer. Отказ/неизвестный ACK → STOP/UNKNOWN_NO_REPLAY, а не повторный CREATE. Новая VM генерирует собственную receipt identity; public key регистрируется через защищённый Git, затем signed INSTALL штатным root owner.
2. **VM readback и внешняя сеть:** exact установленный бинарник/release, root owner/lock/journal/receipt, контейнеры `line1-gateway`, `line2-proxy`, `warp-egress` **3/3**; Line1 **4/4** и Line2 **6/6** endpoints, отдельно TLS/auth, DIRECT и WARP, DNS, firewall, маршруты, negative tests и отсутствие изменений чужого Mesh/Cloudflare One. `container running` или NOOP не являются внешним PASS.
3. **Восстановление:** ровно тем же `/host apply|recover` проверить scoped config-only замену, exact release replacement, reinstall, crash/lost ACK/offline runner, drift, повторный readback и отсутствие replay. `recover` сейчас read-only preflight; новое mutating поведение не объявлять реализованным, пока оно не появилось в Rust и не прошло физическую приёмку. DNS/firewall/host routes изменяются **только адресными native handlers**, если это требуется Git desired; при отсутствии handler — `UNSUPPORTED/BLOCKED`, а не произвольный shell.
4. **Windows отдельно:** сохранить STOPPED/PROXY_ONLY до явного Git desired и операционного допуска; проверить владельца SYSTEM, ACL, signed install/readback, безопасный replace/reinstall/reboot и отдельно TUN, DNS/default route и независимость Cloudflare One. Не включать SCM/TUN как побочный эффект VM acceptance.
5. **Разделение доказательств:** отдельно code gate (CI/ReleaseSet), installed owner gate (authenticated native receipt + poststate), external functional gate (endpoints, TLS/auth/egress). Каждый вывод содержит machine/resource ID, owner, operation ID, exact digest, timestamp, reason и ссылку на свидетельство. Unknown ≠ PASS.

**Критерий окончания:** fresh install → signed scoped apply → точный native readback → независимый внешний тест → safe replace/reinstall/recover для VM и Windows, включая негативные случаи. Не заявлять 10/10 до доказательства **всех** пунктов; если одно не выполнено — указать точный отсутствующий факт, адресный read-only запрос к существующему локальному агенту и состояние `UNPROVEN/BLOCKED`.

## Жёсткие правила на оба среза

- Один Git desired, один Rust decision owner, один Worker secret/signing authority, один VM root Agent / Windows SYSTEM Controller, три команды `/host`. Self-hosted runner — только доставка; без новых SSH transports, сервисов, ручных root scripts, credential adapters, A/B восстановления и отдельных installation workflows.
- Исторический журнал/Issue #26 **не удалять**; его записи не дают право на новые мутации. `UNKNOWN_NO_REPLAY` никогда не повторять; новая транзакция допускается только после проверки владельца/изоляции/неизвестного poststate и нового подписанного operation ID.
- При любой неопределённости — один точный read-only факт `machine/resource/owner/error_class/next_action` от текущего native owner или существующего локального диагностического агента, `MUTATIONS=0`. Исправлять типизированную диагностику, чтобы следующий аналогичный отказ определялся автоматически.
- Защищённый `main` → проверенный кандидат CI → merge exact SHA → immutable ReleaseSet без rebuild → физическая приёмка. Приоритет — **завершить**, а не создавать новые этапы или повторять уже сделанную работу.
