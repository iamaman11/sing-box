Публичный Git `main=e3e23bac6ad074824afa1087ead75dcb08c87f8f` / ReleaseSet `766d7b…` не означает обновление VM. Старый `host-refresh` вызывает журналовый admission scan до замены бинарника; ошибка `HOST_NATIVE_JOURNAL_FILE_UNTRUSTED` блокирует даже read-only обновление. Существующий `local diagnose` не умеет вывести проблемный файл, UID/mode и Line2 exit. **Нельзя восстановить действующий owner одной публикацией кода или новым /host apply.** /host status [#40143570977](https://github.com/iamaman11/sing-box/actions/runs/40143570977): Line2 not running, 51 restarts, Line1/WARP running без health/external acceptance, native receipt UNPROVEN.

**Инженерное решение:** не связывать immutable подписанный `host-refresh` (обновление доверенного бинарника/trust без runtime effects) с полнотой старых resource BEGIN/pending. Проверять неизменяемую идентичность machine/signer/native receipt, root-private journal *directory*, подписанный Git ReleaseSet и root lock; старые journal *entries* не менять вообще. Доступ к новым мутациям по-прежнему блокирует строгий полный scanner, pending и UNKNOWN_NO_REPLAY. Это устраняет **будущий** upgrade-deadlock, но **не переписывает уже установленный старый бинарник**.

**Жёсткий выбор для текущей VM:** без разрешённого root-local witness и owner-controlled binary recovery текущая `application-acceptance-3` остаётся `BLOCKED_AUTHORIZED_WITNESS_UNAVAILABLE`. Нельзя изобретать runtime SSH/sudo/docker shell, chmod, удаления, replay или silent reset. При невозможности штатно восстановить старый owner — использовать только **новый чистый VM epoch** через уже существующий `/host apply` first-use и *новую* Git `machine_id`, **после** exact provider absence, Worker first-use credential provenance, отдельного Git receipt/public signer, Git+CI+ReleaseSet. Старый provider lease не менять/не удалять без отдельного принятого owner-lifecycle и сохранённого evidence; новая VM сама по себе не равна приёмке и не устраняет работающие старые ресурсы.

В этом же кодовом срезе подготовлен **новый, ещё не созданный** Git-only host `application-acceptance-4` с уникальным доменом `stage2-acceptance-4.alegria.by`, прежним Git-accepted VM Worker credential **snapshot pin** (не секретом) и без native receipt. Его статус до first-use: `PROVIDER_ABSENCE_AND_ACCESS_GET_REQUIRED`; создавать только если штатный typed preflight подтвердит EXACT_CREATE_ONLY, отсутствующий provider instance, точные Worker bytes и принятый Git ReleaseSet. Запускать только **одну** новую `/host apply application-acceptance-4` из issue #1; результат UNKNOWN после provider CREATE не повторять. Исторический VM3 остаётся frozen.

**Жёсткое правило:** никакого VM APPLY/RECOVER, ручного chmod/chown, снятия pending, перезапуска/пересоздания контейнеров, SSH-runtime или второго root-транспорта до доказанного protected-local metadata + typed journal/physical readback. Runner-copied status не равно authenticated native owner receipt.

## Срез 1 — адресное исправление диагностики → безопасная VM-приёмка

Срез выполняется **в существующем Rust owner**, без новых служб, workflows, JSON-маршрутов или отдельных планов. Принятый Worker больше не менять.

1. **Срез кода:** атомарно создавать новые pending/BEGIN/terminal journal records Unix `0600` и полно сканировать журнал на admission (PR #476 MERGED). Дополнительно разделить `host-refresh` и mutating journal admission — code-only refresh никогда не выполняет Docker effects и не снимает pending. **Старые файлы не нормализовать и не удалять**. Новые доверенные ошибки делать typed; тесты запрещают снижение root ownership и worker pin.
2. Через существующий root Agent `local diagnose` и `/host status application-acceptance-3 --deep` вернуть ограниченные метаданные файлов (имя/тип/uid/gid/mode/timestamp/size), без secret values. Независимо показывать конкретные typed poststate gate failures, текущие observation reason codes и для owned Line2 exit/restarts/OOM плюс безопасную классификацию log hint (не raw Docker logs). Промаркировать runner-copy как `UNAUTHENTICATED`.
3. Автотесты: `umask 022` → private 0600 при создании; scanner обнаруживает плохой файл **после** pending; no replay для pending/unknown, no mutation при диагностике, no secret leak. Exact candidate CI **6/6**, merge protected main, no-rebuild release promotion. CI подтверждает код, **не VM**.
4. Только при доступном подтверждённом root-owner read-only observation измерить offending journal entry и Line2 exit. Если старый установленный owner по-прежнему заперт, **прекратить повторы status/refresh/apply** и перейти к отдельной чистой VM first-use приёмке через существующий canonical owner chain; не пытаться обновить старый бинарник новым кодом на расстоянии. Сохранить old VM UNKNOWN_NO_REPLAY и provider evidence.
5. Лишь после доказанного и авторизованного решения Root Agent выполнить новый однократный signed HostIntent в строго ограниченном scope; принять signed native terminal receipt, 3/3 owned Docker containers, independent Line1 4/4 и Line2 6/6 TLS/auth/DIRECT/WARP, DNS, network/firewall/routes, и отрицательные scope-тесты чужого Mesh/Cloudflare One.

**Срез 1 закрыт только при полном VM physical PASS.** Промежуточный кодовый merge или 2/3 running — не завершение. Дефект Line2 классифицировать независимо от дефекта journal. Ни одна диагностическая операция не снимает durable pending gate.

## Обязательный контур эксплуатации и наблюдаемости — измеряемая полнота, не root-shell

Первое создание `application-acceptance-4`: GitHub Actions [#40146207282](https://github.com/iamaman11/sing-box/actions/runs/40146207282) завершил provider first-use и root enrollment, создан [PR #478](https://github.com/iamaman11/sing-box/pull/478) с публичным native receipt key. Это **не** финальная VM application acceptance: ключ должен быть слит с зелёным CI, а затем нужен независимый подписанный INSTALL/receipt + проверка 3/3 сетевых линий. Старая VM3 остаётся UNKNOWN_NO_REPLAY.

Уточнённое правило полномочий: установленный `edge-agent` — root owner всей **Git-зарегистрированной VM-подсистемы**, но не произвольный root-shell. Для каждого управляемого ресурса должно существовать ровно одно из: `typed readback`, `typed signed apply`, `typed denied / unsupported`. Права root ≠ разрешение изменить чужой Docker/Network/Mesh, снять pending или обойти Worker signer.

**Транспорт:** GitHub Actions и зарегистрированный self-hosted runner — один основной ingress. Операция всегда различает source/worker trust, online/busy/queued/timeout runner, native process invocation, typed readback и подписанный receipt. Отсутствие runner или ACK = `UNPROVEN/OFFLINE/UNKNOWN_NO_REPLAY`, не повтор и не «всё в порядке». Невозможно гарантировать 100% доступность внешнего GitHub/провайдера; штатная система обязана *диагностировать* потерю доставки без нового SSH/MCP-транспорта.

**Контракт root-local diagnostics:** один bounded `/host status --deep` сообщает для **каждого зарегистрированного контейнера** (не только Line2) точный owner/resource identity, presence/running/health, restart count, exit code, OOM, Docker State.Error как закрытый enum, конфигурацию/image proof, journal root metadata/pending/first-invalid, сетевые DNS/routes/nft reads и credential readback. Только структурированные подтверждённые поля из Root Agent идут в Protobuf ResourceReport; логи/секреты не экспортировать. `UNPROVEN` — отдельное значение, не усреднённое `PASS`. Эти read-only snapshots не могут авторизовать mutation или подменять подписанный receipt. Сетевые внешние TLS/auth/DIRECT/WARP проверки обязательны отдельно.

**Негативные тесты приёмки:** отсутствие root owner, stale ReleaseSet, offline runner, foreign Docker labels, untrusted file, concurrent intent, pending/unknown BEGIN, JSON/приватные значения в логах, Docker/OOM error, конфиг без bound PID должны возвращать конкретную причину без повторов и обходов. Только после независимого end-to-end прогона можно говорить об эксплуатационной надёжности.

## Срез 2 — эксплуатация, recovery и Windows

После приёмки VM, не параллельным обходом:

1. **Эксплуатационный цикл VM:** Scoped config-only Line1/Line2 без чужих изменений; exact ReplaceRelease/reinstall, offline runner, crash/unknown ACK, drift и typed `/host recover`. Сейчас `recover` — VM **code-only root refresh плюс read-only diagnosis** (отдельно от resource mutation и NO_REPLAY); Windows пока read-only preflight. Mutating recover добавлять лишь в существующий native owner с typed handler, журналом и отдельной проверенной транзакцией. Отсутствующие handlers host DNS/firewall/routes остаются `UNSUPPORTED`, не shell/docker exec.
2. **Windows:** защищённый SYSTEM Controller/SCM, ACL и точный release install/readback; безопасный ProxyOnly lifecycle, replace/reinstall/rollback/reboot с native receipt. Windows сейчас **STOPPED/PROXY_ONLY**, SYSTEM apply/TUN ещё не приняты. Managed TUN, DNS leak/IPv6, default routes и сосуществование с Cloudflare One — отдельная физическая матрица только после Git desired и разрешения; чужой адаптер/службу не изменять.
3. **Архитектурный долг, только с доказанным потребителем:** заменить оставшиеся исполняемые `grep/sed` admission-проверки на закрытый Rust/Protobuf verifier в том же owner и убрать действительно нулевых потребителей старых mutating helpers. Не запускать самостоятельную бесконечную «очистку» файлов. Новая capability: `Protobuf → Rust DAG/planner → существующий native handler → typed readback → signed receipt → physical acceptance`.

**Конечный PASS:** две платформы устанавливаются, диагностируются, ограниченно перенастраиваются, обновляются и восстанавливаются **исключительно** четырьмя `/host` командами, с единым Git/Worker/root|SYSTEM owner chain, без произвольных команд, повторов UNKNOWN, лишних transport/secret registries, скрытых rollback. Независимо приняты network/TLS/auth/egress и негативные тесты. До этого проект `NOT_ACCEPTED_10_10`.

## Дополнение к принятому интерфейсу: GH-runner native diagnostics (#484)

В составе PR #485 реализуется четвёртый операторский ввод `/host diagnose <machine> <approved argv>` через существующий Issue #1, точную Git-регистрацию и self-hosted runner. Команда несёт закрытый Protobuf request и исполняет только наблюдение с uid/gid 65534, ограниченным argv/time/output в существующем Root Agent. Новый сервис, MCP, SSH или shell-доступ runner не создаются. Результат `RUNNER_COPIED_UNAUTHENTICATED` — не подписанная физическая квитанция и не разрешение изменять ресурсы.

До отдельно проверенной установки точного нового Root Agent и sudoers и до физической доставки runner статус остаётся `NOT_ACCEPTED`. Любой прежний pending `UNKNOWN_NO_REPLAY` сохраняется без повторного INSTALL. Полное административное выполнение root и FULL_CONTROL из #484/#480 **не являются реализованными** одной диагностикой.

## Постоянные правила

- Один канонический `main` и Git desired, один immutable ReleaseSet, один Rust decision owner, один Cloudflare Worker credential/signing plane, один VM root Agent / Windows SYSTEM Controller. GitHub Actions/runner — доставка, не физический mutation owner.
- Исторические PR, issue/runner logs, Windows/WSL старые runbook — **свидетельства**, не допуск операции. Issue #26 сохранять; **не повторять** failed/unknown BEGIN/HostIntent. Отсутствие факта → **один адресный read-only запрос** существующему локальному агенту (никакого секрета в чат/GitHub).
- Сохранить source/provenance и install/external gates раздельными. Новую физическую операцию разрешать только после точной независимой сверки текущего provider/journal poststate и с новым подписанным operation ID.
- Приоритет: закончить сквозную физическую приёмку, а не плодить новые планы/этапы/службы/адаптеры.
