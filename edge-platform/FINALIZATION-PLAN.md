## Инварианты, а не второй план

- Один привилегированный Root Agent на VM; Windows имеет собственный SYSTEM owner. GitHub Actions и self-hosted runner — только транспорт. Worker разрешает и подписывает точные операции.
- Root Agent исполняет произвольные одобренные административные программы на своей VM, в том числе заранее неизвестные команды и системные инструменты. Ограничений по списку исполняемых программ **нет**; проверка подписи, машины, срока, журнала и запрет повторения неопределённых эффектов обязательны. Runner не получает общего root, Docker socket или долговременные секреты.
- Единственная будущая первичная установка VM: Git-проверенный Vultr CREATE без SSH → cloud-init → проверенный Root Agent → непривилегированный runner → проверенная регистрация публичной квитанции в Git → зашифрованная root-only доставка Access identity. Полная процедура остаётся **BLOCKED**, пока не пройдёт сквозную физическую приёмку.
- `/host status --deep`, `/host apply` и `/host recover` должны отличать `SUPPORTED_CODE`, `INSTALLED_PROVEN`, `PHYSICAL_ACCEPTED`, `UNSUPPORTED`, `BLOCKED`. CI или Git-квитанция по отдельности не являются физической приёмкой.
- Старые VM3/VM4, исходы `UNKNOWN_NO_REPLAY`, pending и старые INSTALL нельзя автоматически повторять или тихо «восстанавливать». Новую VM создаём только по принятому плану #538 после доказанной готовности кода.

*Предыдущие детальные планы и снимки от 24 октября доступны в истории этого файла, но не являются действующей инструкцией. Изменения требований и актуальный курсор закреплять в #538, физическую матрицу — в #480, не создавать параллельные документы.*
